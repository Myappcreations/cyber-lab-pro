Security Headers & Secure API Design

Learn how response headers help protect web applications, and understand CORS without confusing it with authentication.

1. Security Headers అంటే ఏమిటి?

HTTP Responseలో Server కొన్ని అదనపు instructionsను Headers రూపంలో Browserకి పంపుతుంది. వీటిలో కొన్ని browser behaviorని నియంత్రించి common web risks తగ్గించడంలో సహాయపడతాయి.

  • Content-Security-Policy (CSP): ఏ sources నుంచి scripts, styles, images load కావాలో నియంత్రిస్తుంది.
  • Strict-Transport-Security (HSTS): Browserను HTTPS connection ఉపయోగించమని సూచిస్తుంది.
  • X-Content-Type-Options: nosniff: Browser MIME typeని ఊహించి contentని వేరే విధంగా interpret చేయకుండా సహాయపడుతుంది.
  • frame-ancestors (CSP): మీ pageని ఏ sites frameలో embed చేయవచ్చో నియంత్రిస్తుంది. ఇది clickjacking risk తగ్గిస్తుంది.
  • Referrer-Policy: ఇతర sitesకి navigation చేసినప్పుడు ఎంత referrer information పంపాలో నియంత్రిస్తుంది.

Security headers ఒక్కటే complete security కాదు. Secure coding, authentication, authorization మరియు server configuration కూడా అవసరం.

3. CORS — What does it do?

CORS (Cross-Origin Resource Sharing) అనేది Browser అమలు చేసే policy mechanism. ఒక Web Page వేరే Originలో ఉన్న APIని access చేయడానికి Server ఏ originsకి అనుమతి ఇస్తుందో Response Headers ద్వారా తెలియజేస్తుంది.

Origin అంటే scheme + host + port. ఉదాహరణకు https://app.example మరియు https://api.example వేర్వేరు origins.

ముఖ్యమైన విషయం: CORS అనేది Authentication లేదా Authorizationకి ప్రత్యామ్నాయం కాదు. CORS allow చేసినా Server ప్రతి requestకి user permission verify చేయాలి.

4. Secure API Design Checklist

  • Use HTTPS everywhere; configure HSTS carefully after HTTPS is fully enabled.
  • Set a restrictive CSP and test it before enforcing in production.
  • Use X-Content-Type-Options: nosniff.
  • Use CSP frame-ancestors to control framing.
  • Configure CORS with specific trusted origins; avoid wildcard origins when credentials are involved.
  • Never rely on CORS as access control. Enforce authorization on the server for every endpoint and object.
  • Keep API secrets out of browser JavaScript and public repositories.
  • Log security events safely and avoid exposing stack traces or secrets in errors.
Content-Security-Policy: default-src 'self'; object-src 'none'; frame-ancestors 'none'
Strict-Transport-Security: max-age=31536000
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin

Example policies need adjustment for each application. Do not copy a CSP blindly; test required scripts, styles, APIs and integrations first.
