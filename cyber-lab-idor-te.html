IDOR & Broken Access Control ల్యాబ్

ఒక Record ID తెలుసుకోవడం మాత్రమే దాన్ని చూడటానికి అనుమతి కాదు — ఈ విషయాన్ని సురక్షితమైన Simulation ద్వారా నేర్చుకుందాం.

1. IDOR అంటే ఏమిటి?

IDOR (Insecure Direct Object Reference) అనేది ఒక Access Control లోపం. ఒక Website లేదా Appలో Invoice ID, Account ID వంటి Object Reference ఉంటుంది. కానీ ఆ డేటాను చూడటానికి ప్రస్తుత Userకు అనుమతి ఉందో లేదో Server తనిఖీ చేయకపోతే IDOR సమస్య వస్తుంది.

ఉదాహరణ: Alice తన Invoice INV-1001 చూడగలదు. ఆమె IDని INV-2002గా మార్చినప్పుడు Server Bob యొక్క Invoiceను కూడా చూపిస్తే, అది Broken Access Control సమస్య.

ID మార్చడం ఒక్కటే Vulnerability కాదు. Serverలో Ownership / Permission Check లేకపోవడమే అసలు సమస్య.

2. Invoice Access Simulator

ఇక్కడ Alice లేదా Bobను ఎంచుకుని, Invoice IDను Request చేయండి. Unsafe Demoలో Ownership Check లేకపోవడాన్ని, Secure Demoలో Server Ownership Checkను పోల్చి చూడండి. ఇవన్నీ కల్పిత డేటా మాత్రమే.

3. సరైన Security Rule

Browser పంపిన Record IDను మాత్రమే నమ్మకూడదు. Server, Login అయిన Userను Session ద్వారా గుర్తించి, ఆ Recordను చూడటానికి Permission ఉందో లేదో తనిఖీ చేసిన తర్వాతే డేటా పంపాలి.

// Server-side Authorization భావన
invoice = findInvoice(requestedInvoiceId)

if invoice.ownerId != authenticatedUser.id:
    return 403 Forbidden

return invoice

ఇది అర్థం చేసుకోవడానికి ఇచ్చిన Pseudocode మాత్రమే. నిజమైన Appsలో Roles, Sharing, Tenant మరియు ఇతర Business Rules కూడా తనిఖీ చేయాలి.

5. మీ ప్రాక్టీస్ టాస్క్

ముందుగా Aliceను ఎంచుకోండి. తర్వాత INV-2002ను Request చేయండి. Unsafe మరియు Secure ఫలితాలను పోల్చండి. ఇప్పుడు Bobను ఎంచుకుని అదే Invoiceను Request చేయండి.

మీరు వివరించాల్సింది: Secure Check ఒకరికి Access ఎందుకు ఇస్తుంది? మరొకరికి ఎందుకు నిరాకరిస్తుంది?
