Cross-Site Scripting (XSS) Lab

Learn how unsafe content handling can affect a browser — with a safe, local simulation.

1. XSS in simple words

XSS happens when an application places untrusted input into a web page unsafely. The browser may interpret that input as HTML or JavaScript instead of displaying it as ordinary text.

  • Stored XSS: input is saved (such as a comment) and shown to users later.
  • Reflected XSS: input is immediately reflected in a response page.
  • DOM-based XSS: client-side JavaScript handles untrusted data unsafely and changes the page.

This lab never executes submitted HTML or JavaScript. It only demonstrates the security difference.

3. XSS prevention

  • Use textContent to display plain text.
  • Use context-aware output encoding for HTML, attributes, URLs, CSS, and JavaScript contexts.
  • Avoid inserting untrusted input with innerHTML.
  • If rich HTML is required, use a reputable maintained sanitizer with a strict allowlist.
  • Use Content Security Policy (CSP) as an additional layer, not the only fix.
Safer pattern
const comment = userInput;
document.querySelector("#commentBox").textContent = comment;
Risky pattern — do not use with untrusted input
document.querySelector("#commentBox").innerHTML = userInput;

These are teaching examples; this lab does not run the risky pattern.
