Authentication & Session Security Lab

Practice the difference between proving identity, maintaining a session, and checking permissions.

1. Three important ideas

  • Authentication: Who are you? The application verifies identity.
  • Session management: How does the application remember that you signed in?
  • Authorization: What are you allowed to access? The server must check permissions for every protected action or object.

Successful login does not automatically permit access to every record.

4. Security checklist

  • Hash passwords with a modern algorithm such as Argon2id, bcrypt, or scrypt — never store plaintext passwords.
  • Use HTTPS and secure cookie attributes: HttpOnly, Secure, and suitable SameSite.
  • Regenerate session identifiers after login and privilege changes.
  • Expire sessions and invalidate them on logout.
  • Check authorization on the server for every protected resource and action.
  • Use MFA where appropriate, rate limits, and safe error messages.

This demo does not implement production authentication, password hashing, cookies, or real server sessions.
