1. What is IDOR?

Insecure Direct Object Reference (IDOR) is an access-control weakness where an application exposes an object reference (such as an invoice ID or account number) and fails to verify that the current user is allowed to access that object.

Example: Alice is signed in and can view invoice INV-1001. If she changes the reference to INV-2002 and the server returns Bob's invoice without checking ownership, that is a broken access-control issue.

Changing an ID is not automatically a vulnerability. The security failure is missing server-side authorization.

3. The security rule

Do not trust a record ID supplied by the browser. The server must identify the authenticated user from the session and check permission before returning the record.

// Conceptual server-side authorization
invoice = findInvoice(requestedInvoiceId)

if invoice.ownerId != authenticatedUser.id:
    return 403 Forbidden

return invoice

Illustrative pseudocode only. Real applications also need tenant, role, sharing, and business-rule checks where applicable.
